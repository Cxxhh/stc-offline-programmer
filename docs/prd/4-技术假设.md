# 4. 技术假设

### 4.1 仓库结构

**结构类型**: Monorepo

本项目采用单一仓库结构，所有代码（HAL/BSP/Service/APP）在同一仓库内管理，便于版本控制和依赖管理。

### 4.2 服务架构

**架构类型**: 分层单体架构（含Port层抽象）

```
┌─────────────────────────────────────────────────────────────────────────┐
│                              APP Layer                                   │
│                    (app_main, app_ui, app_isp)                          │
│                      业务逻辑 / UI交互 / 流程控制                          │
├─────────────────────────────────────────────────────────────────────────┤
│                           Service Layer                                  │
│              ┌─────────────┬─────────────┬─────────────┐                │
│              │  ISP Core   │  File Mgr   │   Config    │                │
│              │  烧录状态机  │  固件管理   │   配置管理   │                │
│              └─────────────┴─────────────┴─────────────┘                │
├─────────────────────────────────────────────────────────────────────────┤
│                         Middlewares Layer                                │
│       ┌──────────┬──────────┬──────────┬──────────┬──────────┐         │
│       │  FatFs   │   Log    │ RingBuf  │ Protocol │  MCU DB  │         │
│       │ 文件系统  │  日志    │ 环形缓冲  │ ISP协议  │ 型号数据  │         │
│       └──────────┴──────────┴──────────┴──────────┴──────────┘         │
├─────────────────────────────────────────────────────────────────────────┤
│                         Device Layer (BSP)                               │
│       ┌─────────────────────────────────────────────────────────┐       │
│       │              Unified Device Interface                    │       │
│       │                 统一设备接口抽象                          │       │
│       ├─────────────────────────────────────────────────────────┤       │
│       │   Serial Dev   │   Display Dev   │   Storage Dev        │       │
│       │   串口设备      │    显示设备      │    存储设备          │       │
│       └─────────────────────────────────────────────────────────┘       │
├─────────────────────────────────────────────────────────────────────────┤
│                      Platform Port Layer (HAL)                           │
│       ┌───────────────┬───────────────┬─────────────────────────┐       │
│       │  STM32G4 Port │  STM32F1 Port │   Other MCU Port        │       │
│       │   (LL库实现)   │   (LL库实现)  │     (待扩展)            │       │
│       └───────────────┴───────────────┴─────────────────────────┘       │
└─────────────────────────────────────────────────────────────────────────┘
```

**设计原则**:
- 单向依赖：只允许上层调用下层
- 接口隔离：每层通过统一接口对外暴露功能
- 依赖注入：上层模块不直接依赖具体实现，运行时注册设备实例
- 可替换性：更换平台只需重写Port层，BSP层设备实现可独立替换

### 4.3 测试需求

**测试策略**: Unit + Integration

- **单元测试**: 协议解析、数据校验、状态机逻辑
- **集成测试**: 串口通信、SD卡读写、完整烧录流程
- **手动测试**: 实际STC芯片烧录验证

### 4.4 其他技术假设与要求

**硬件平台**
- MCU: STM32G431RBTx (ARM Cortex-M4, 80MHz, 128KB Flash, 32KB SRAM)
- 开发环境: Keil MDK-ARM
- 底层库: STM32 LL库（非HAL库）

**通信配置**
- 目标通信: USART2 (PA2/PA3)，支持动态波特率和校验位切换
- 调试输出: USART1 (115200, 8N1)
- SD卡通信: SPI1

**外部依赖**
- FatFs: 文件系统中间件（SD卡固件存储）
- MCU数据库: 源自stcgal开源项目（1140型号）

**编码规范**
- 遵循嵌入式5层架构规范
- 函数命名: `hal_xxx()`, `bsp_xxx()`, `svc_xxx()`, `app_xxx()`
- 返回值约定: 0=成功, 负数=错误码

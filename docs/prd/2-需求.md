# 2. 需求

### 2.1 功能需求

**核心功能（P0 - 必须实现）**

- **FR1**: 系统应支持通过UART与STC目标单片机通信，实现ISP握手协议
- **FR2**: 系统应能通过Magic码自动识别目标STC单片机型号（支持1140+型号数据库）
- **FR3**: 系统应支持将用户代码烧录到STC单片机的Code Flash区域
- **FR4**: 系统应支持对STC单片机进行全片擦除操作
- **FR5**: 系统应在烧录完成后进行数据完整性校验，确保烧录正确
- **FR6**: 系统应支持STC89/10/11系列（8N1模式）和STC12/15/8系列（8E1偶校验模式）的串口配置切换
- **FR7**: 系统应支持动态波特率切换，握手阶段使用低速（2400bps），数据传输阶段协商高速（最高230400bps）

**扩展功能（P1 - 应该实现）**

- **FR8**: 系统应支持将数据烧录到STC单片机的IAP/EEPROM区域
- **FR9**: 系统应通过LCD显示目标MCU的型号、Flash大小、UID等设备信息
- **FR10**: 系统应支持从SD卡读取HEX/BIN固件文件进行烧录
- **FR11**: 系统应支持在SD卡上存储和管理多个固件文件
- **FR12**: 系统应提供按键操作界面，支持固件选择、烧录启动、状态查看等基本操作

**高级功能（P2 - 可以实现）**

- **FR13**: 系统应支持STC15/8系列的内部RC振荡器频率校准功能
- **FR14**: 系统应支持配置目标MCU的熔丝位/选项字节
- **FR15**: 系统应支持测量目标MCU的实际工作频率

**未来功能（P3 - 后续版本）**

- **FR16**: 系统应支持批量烧录模式，实现连续自动烧录
- **FR17**: 系统应支持STC32系列（MCS-251架构）单片机的烧录

### 2.2 非功能需求

**性能需求**

- **NFR1**: 握手响应时间应小于3秒（包含目标MCU冷启动时间）
- **NFR2**: 单次烧录64KB代码的时间应小于30秒（不含擦除时间）
- **NFR3**: 系统应支持连续工作8小时以上无异常

**可靠性需求**

- **NFR4**: 烧录成功率应达到99.9%以上
- **NFR5**: 系统应具备通信超时检测和错误重试机制
- **NFR6**: 系统应在烧录失败时提供明确的错误提示

**可维护性需求**

- **NFR7**: 代码应遵循嵌入式分层架构规范（Port/BSP/Middlewares/Service/APP）
- **NFR8**: 模块间应通过统一设备接口通信，采用依赖注入保持低耦合高内聚
- **NFR9**: MCU数据库应支持独立更新，无需重新编译整体固件

**资源约束**

- **NFR10**: 固件大小应控制在128KB Flash以内（STM32G431RBTx限制）
- **NFR11**: 运行时RAM占用应控制在32KB以内（STM32G431RBTx限制）
- **NFR12**: 应优先使用LL库而非HAL库，以优化代码体积和执行效率
